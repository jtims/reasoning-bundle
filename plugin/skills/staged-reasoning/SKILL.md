# Staged Reasoning

Skipping straight to a solution is the most common way to solve the wrong problem. This skill
imposes ordered stages with a gate between them, so each stage is grounded before the next begins.

Derived from the Frontier Operating Manual (S2 - decompose by verifiability; run the kill-shot first).

## The stages (do not skip; revisit an earlier one when a later stage contradicts it)

1. **Define.** State the actual problem and the acceptance test for a good answer. If you cannot
   write the pass/fail check, you do not yet understand the problem - stay here.
2. **Decompose by verifiability.** Split into pieces that each get their own pass/fail check,
   written BEFORE work starts. Order them so the piece whose failure invalidates the most
   downstream work runs FIRST (the kill-shot).
3. **Research.** Gather what each piece needs from the best available source (execute it >
   primary artifact > current doc > memory). Label each finding by how you know it.
4. **Analyze.** Reason over the evidence. Keep each inference chain short and name the premise
   it rests on.
5. **Synthesize / conclude.** Assemble the answer, answer-first, load-bearing claims labeled,
   residual risk stated.

## The gate between stages

Before advancing, ask: is this stage actually DONE, or am I advancing because I want to be? A gate
you always pass is not a gate. If the kill-shot piece failed, STOP - the downstream stages are moot.

## Boundary

Advisory reasoning discipline. Composes with `devils-advocate` (attack the staged conclusion),
`decision-matrix` (when the analyze stage is a choice among options), and `logic-check` (when the
conclusion is an argument whose validity matters).
